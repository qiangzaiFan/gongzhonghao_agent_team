# 体制内清醒生活公众号 Agent 设计

日期：2026-07-31  
状态：已获用户口头确认，等待用户复核书面 spec

## 背景

用户希望基于本地参考语料目录：

`D:\自媒体\知识库\01-公众号文章\体制内公众号文章`

目录下 4 个博主文章，创建一个新的长期公众号内容 agent。该 agent 用于生产体制内赛道公众号文章，发布前需要达到项目其他赛道相同的本地中文 AIGC 检测线。

项目现有赛道采用独立目录模式，例如 `elder_healing_agent/`、`emotion_women/`、`food_home_cooking/`。新赛道应遵循同类结构：`README.md`、`CLAUDE.md`、`.claude/agents/`、`specs/`、`references/`、`data/`、`templates/`、`articles/`、`reviews/`、`runs/` 和质检脚本。

## 目标

创建新目录 `system_inside_life_agent/`，作为“体制内清醒生活”公众号 agent 工作区。

核心定位：

> 写给体制内普通人的清醒生活号：少背锅、少内耗、懂边界、会留痕、看清规则，但不怂恿对抗，也不制造怨气。

账号采用“四栏目矩阵 + 爆款拆解加速器”的设计：

- 四栏目矩阵负责长期稳定生产。
- 爆款拆解 agent 负责从参考语料或指定爆文中提取标题钩子、读者痛点、结构节奏和评论点。
- 标题允许原创、参考结构改写，也允许在人工确认下复用参考库标题。
- 正文必须原创，不复用参考博主原句、案例、署名、连续段落或可识别正文结构。

## 非目标

- 不接入微信公众号自动发布；任何 `--publish`、草稿箱上传、凭证读取都另行确认。
- 不创建绕过 AIGC 检测的扰乱文本流程。
- 不复制参考博主正文、图片、署名、人设或可识别案例。
- 不把政策、纪检、组织、人事问题写成未经核实的事实断言或可执行违规建议。

## 参考语料用途

参考目录包含 4 个博主子目录：

- `安小渔`
- `田间烟火`
- `烟火里的小安稳`
- `老周的建议`

参考库用于：

- 抽取标题外壳、标题高频词、栏目主题和爆款切入方式。
- 统计篇幅、段落密度、小标题、图片数量和常见痛点。
- 生成 `data/reference_titles.txt`、`data/style_stats.json`、`references/corpus_report.md`。
- 在质检时进行标题撞题、正文近似片段和风险表达检查。

参考库不用于：

- 逐段改写原文。
- 复用原文案例、私人经历、署名、图片和固定表达。
- 模仿到让读者误认为同一作者或同一账号。

## 栏目矩阵

### 新人避坑

读者：刚上岸、刚进单位、刚换岗的年轻体制人。

主题：汇报、材料、领导沟通、拒绝、留痕、不会做人、怕背锅。

典型标题外壳：

- 刚进体制内，最该学会的不是努力，而是这 3 件小事
- 为什么越老实的新人，越容易被安排杂活
- 体制内新人不要急着表现，先把这几个坑避开

### 基层现场

读者：乡镇、街道、村社、基层条线干部。

主题：群众工作、问责、台账、检查、执法、分工、值班、加班和身心消耗。

典型标题外壳：

- 为什么乡镇干部越规范，反而越容易累
- 基层最怕的不是忙，而是这类事说不清
- 乡镇工作里，真正消耗人的从来不是一件大事

### 人情关系

读者：被同事关系、饭局、送礼、人情、婚恋和家庭压力困住的体制人。

主题：同事边界、领导情绪、饭局、送礼、相亲、婚姻、亲戚眼光。

典型标题外壳：

- 体制内，人情可以懂，但不要把自己搭进去
- 为什么有些人不怎么干活，关系却越来越稳
- 体制内相亲，最该看清的不是条件，而是这件事

### 中年求稳

读者：30-50 岁之间开始祛魅、求稳、想调动或等退休的体制内人。

主题：提拔祛魅、调动、退休预期、降薪、家庭压力、躺平、精神自保。

典型标题外壳：

- 体制内到了一定年纪，最好的活法是少内耗
- 为什么很多人不再想提拔了
- 人到中年还在体制内，真正要守住的是这三样

## Agent 组成

### system-title-editor

标题官。输入主题、栏目、标题模式和参考范围，输出 12 个标题：

- 4 个参考结构改写标题。
- 4 个原创爆款标题。
- 4 个低风险稳妥标题。

标题模式：

- `original`：完全原创，默认低风险模式。
- `inspired`：复用参考标题结构，但更换主题、对象、判断和表达。
- `reference`：允许使用参考库标题或高度接近标题；质检标红，要求人工确认后进入发布流程。

输出同时包含标题钩子说明、适合栏目、风险等级和推荐标题。

### system-hotspot-analyst

爆款拆解官。输入参考文章、参考标题或指定本地文件，输出爆款拆解卡：

- 标题钩子。
- 目标读者。
- 痛点入口。
- 冲突或反差。
- 结构节奏。
- 评论区可讨论点。
- 可转化的新选题。
- 不可复用内容清单。

该 agent 不生成正文，只给标题官和写手提供可原创转化的选题依据。

### system-inside-writer

矩阵写手。输入选题卡、栏目和标题，产出 Markdown 草稿。

默认要求：

- frontmatter 只写 `title`。
- 正文目标 900-1300 个中文字符。
- 前 150 字内出现痛点、场景或判断。
- 至少出现 3 个具体体制内生活物件或动作，例如材料、会议通知、工作群、台账、请示、值班表、饭局、调动表、考核表、办公室灯。
- 允许 1-3 个二级小标题，但不要写成培训课件。
- 结尾落到一个可执行的小动作，例如留痕、少说一句、先问清边界、把材料备份、晚上早点睡。

### system-chief-editor

主编二审。负责把稿件从“像机器生成的体制文”改成“公众号可读的原创稿”。

检查项：

- 标题是否撞参考库标题。
- 正文是否复用原句、案例、署名或可识别段落。
- 是否有未经核实的政策、纪律、组织、人事断言。
- 是否给出违规送礼、规避审查、对抗组织或攻击具体单位的建议。
- 是否只剩怨气，没有回到边界、自保、留痕、生活动作。
- 是否存在明显机器稿味。

## 数据流

常规生产：

```text
30 天游题表或自定义主题
→ system-title-editor 生成标题组
→ system-inside-writer 写原创初稿
→ system-chief-editor 二审
→ quality_gate.py
→ ai_detector.py
→ 人工发布前复核
```

爆款拆解生产：

```text
参考文章或指定文章
→ system-hotspot-analyst 输出爆款拆解卡
→ system-title-editor 生成标题组
→ system-inside-writer 原创转化
→ system-chief-editor 二审
→ quality_gate.py
→ ai_detector.py
→ 人工发布前复核
```

生产包脚本 `pipeline.py` 生成 `runs/` 下的 runbook，包含标题官任务、爆款拆解任务、写手任务、主编二审任务和质检命令。

## 质检设计

`quality_gate.py` 采用 100 分制，基础发布建议：

- 90-100：可进入人工发布前复核。
- 85-89：按 warning 轻改。
- 75-84：必须二审重改。
- 75 以下：重写。

检查项：

- frontmatter 是否只有 `title`。
- 标题长度、标题模式、标题参考风险。
- 标题是否出现在 `data/reference_titles.txt`。
- 正文中文字符数是否在 900-1300。
- 是否包含栏目需要的具体生活细节。
- 是否有 1-3 个小标题。
- 是否有空泛鸡汤、过密感叹号、公众号机器稿套话。
- 是否出现禁用风险表达。
- 是否与参考库或历史稿存在连续片段重合。

`reference` 标题模式不自动阻止生产，但会输出人工确认提示。

## AIGC 检测

新赛道复用现有本地中文 AIGC 检测口径：

- 发布线：`human≥90%` 且 `ai≤10%`。
- 检测报告保存到 `reviews/auto/`。
- 报告绑定当前正文 SHA-256。
- 正文改动后必须重跑。

未通过时，返工方向是补真实语境、删模板话、调整段落节奏、加入具体动作和克制判断；不通过错别字、随机扰乱、符号噪声来对抗检测。

## 风险策略

体制内内容涉及组织、人事、纪检、政策、单位关系和职业建议，风险高于普通情感文。默认规则：

- 不写具体单位、具体人员可识别信息。
- 不编造政策、处分、工资、退休待遇或组织流程事实。
- 不给规避纪检、规避审查、违规送礼、删证据、对抗调查等建议。
- 涉及政策、法律、财务、医疗、组织纪律时，必须标注人工复核。
- 对领导、同事、群众和组织的表达保持克制，不制造仇恨和对立。

## 错误处理

- 参考目录不存在：语料分析脚本停止并提示路径。
- 参考文章为空或非 Markdown：跳过并记录 warning。
- 标题库为空：只生成原创标题，并提示先运行语料分析。
- 选题卡缺栏目：默认进入 `新人避坑`，同时输出 warning。
- AIGC 报告 hash 不匹配：视为未检测。
- 质量分低于发布线：生产包保留稿件，但 runbook 标记为返工。

## 测试与验证

实现阶段需要验证：

- `scripts/analyze_reference_corpus.py` 能从 4 个博主目录生成标题库和统计报告。
- `pipeline.py --topic "体制内新人最怕背锅"` 能创建完整 runbook。
- `daily_system_inside.py --calendar-day 1` 能生成写手任务。
- `quality_gate.py` 能识别标题撞题、篇幅不足、风险词和空泛表达。
- `ai_detector.py` 能复用项目现有检测方式并输出报告。

不在首版实现：

- 自动抓公众号链接。
- 自动发布到微信公众号草稿箱。
- 自动生成配图。
- Web 管理界面。

## 接受标准

首版完成后应具备：

- 新目录 `system_inside_life_agent/` 结构完整。
- 4 个 Claude agent 定义可直接调用。
- 至少 8 个规格文档覆盖定位、栏目、标题、爆款拆解、写作、风险、流程和 30 天游题。
- 语料分析脚本能生成参考标题和统计报告。
- 生产包脚本能生成标题、拆解、写手、主编和质检任务。
- 质检脚本能给出可执行的错误和警告。
- AIGC 检测与项目其他赛道保持同一发布线。
